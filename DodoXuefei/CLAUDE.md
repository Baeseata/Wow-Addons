# DodoXuefei — 血 DK「沸点」监视(独立版)

屏幕上一格血液沸腾的图标,盯的是「这一发血沸有没有被沸点强化」:

```
灰 = 什么都没有(常驻,1.1 加的;透明度可调,调到 0 就回到"整格透明")
绿 = 沸点 proc(15 秒)                     倒计时归**暴雪**画
红 = 那一发自动血沸还有几秒落地(3 秒)      我们自己算
有红显红、没红有绿显绿,都没有就显灰;绿和红都发光。
```

🔑 那张灰图是**我们自己画的静态贴图**(`SetDesaturated` 真去色),不是容器画的 ——
容器只在光环真的挂着时才给你一个 button。「灰掉」和「多淡」是**两件事**:
去色写死,淡到什么程度归 `idleAlpha` 那条滑条。

`/dxf` 看命令。当前版本以 `DodoXuefei.toc` 的 `## Version` 为准。

## 🔴 机制事实(2026-08-23 在 12.1.0 build 69404 真机全部复核过)

出处 = SimC `sc_death_knight.cpp:15219`;`Core.lua` 顶部那张 `ID` 表是**事实的锚点**,
任何一条对不上先改那张表,别改逻辑。

- 窗口是 **15 秒**不是 12(量到 12.92s 那发心脏打击续期 → 15.03s 后过期)
- 🔴 **续期时 `GLOW_SHOW` 不重发** ⇒ 自己计时会系统性撒谎(一次实测差 10.8 秒)
  ⇒ **绿色那半的倒计时只能交给暴雪画**,这就是它必须走 `AuraContainer` 的原因
- echo 落地**不发 `UNIT_SPELLCAST_SUCCEEDED`** ⇒ 红色那 3 秒只能自己算
- echo 会**吃掉新 proc** 并再排一个 3 秒(能连锁),只能靠
  「无人施法的 `GLOW_HIDE` 正好赶上 echo 落地(±0.3s)」认出来
- 战斗中光环被**扣值**(`ShouldAurasBeSecret` 为真、HELPFUL 枚举 ERROR)⇒ 我们读不到 expirationTime,
  而容器跑在 C 层拿真数据 ⇒ **它画得出来**。「绿现在亮着吗」也不能问容器
  (`AuraButton:IsShown()` 是 secret),拿 `IsSpellOverlayed(血沸)` 当代理(明文 bool)

## 🔴 尺寸有**三个**消费方,少碰一个就是「半生效」

外框 `slot:SetSize` · 容器的 flow layout(`SetAuraGroupLayout`)· **已经建出来的那些 button**。
第三个最容易漏,而且**碰它有闸**:`CanTouchButtons()`(战斗中 / 光环被扣值时碰不得,
碰了不是报错、是整个初始化被掀掉)。碰不得就记 `needsResize`,`PLAYER_REGEN_ENABLED` 补上 ——
不记账的话「战斗中拖了滑条」那次改动**永远丢了**,而外框已经变了 ⇒ 半生效比不生效更难查。

⇒ **改尺寸只有 `ApplyGeom` 一个入口**,滑条 / 输入框 / `/dxf w` 全走它。
`SetAuraGroupLayout` 这个 API 是从**本机在产插件**里 rg 出来的(DodoNameplate `Auras.lua:262`、
DodoGrid `Auras.lua:474`)—— canon 那条「三个源分工:契约答能不能碰、探针答给不给值、
在产插件答实际怎么写」,这次省掉了一整轮探针往返。

## 🔴 判据只在一处声明

| 判据 | 住哪儿 | 别在别处再判一遍 |
|---|---|---|
| 该不该出现 | `eligible()` | 面板、斜杠命令都只调 `Evaluate()` |
| 尺寸上下限 / 空串怎么办 | `ClampDim` | 滑条和输入框都不许自己钳 |
| 玩家允不允许显示 | `ns.SetSlotShown` | `ShowSlot/HideSlot` 是**纯动作**:不吭声、不写存档、不做判断 |

早先把「清 `manualOff`」写在 `ShowSlot` 里,后果是面板上勾一下「显示」就**无条件**显示 ——
法师身上也会冒出一个永远空的框,而那看起来完全像插件坏了。

## 🔴 存档:默认值一个字都不写进去

每次读都走带回落的取值器(`Num`),存档里只留玩家真改过的东西。
理由是 DodoCombatHUD 0.12 栽过那条:`db.x = db.x or 默认` 的 `or` **只在键不存在时生效**
⇒ 某一版把默认值落了盘,以后再改默认值对那个人**一点用都没有**,而自动路径是静默的。
同一条的另一面:「缺省该是开」的开关存**反面**(`manualOff` 缺席 = 显示),清掉时**删键不写 false**。

⚠ **`a and nil or b` 恒等于 `b`**(`and nil` 必然假,永远落到 `or` 那一支)。
写这插件时我自己踩了一次:`DB.manualOff = v and nil or true` ⇒ 勾「显示」反而把它关掉,
**两个方向都错**。⇒ 一律展开写成 if/else;`tools/test_dxf.lua` 有一条守卫钉着它。

## 面板(`Options.lua`)

ESC → 选项 → 插件 → DodoXuefei。一页:显示 / 解锁移动 / 宽 / 高 / **不触发时的透明度**(后三个都是滑条 + 数字输入框,共用同一份 `Col:Num`)。

- **布局是游标式的(`Col:take`),页面里一个 y 坐标都不许写。** DodoCombatHUD 0.13.0 手写 y
  真机满屏文字互相压 —— 说明文字换行成几行只有运行时才知道,手写 y 等于替一个你算不出来的量猜常数。
- **这个文件一处都不碰 `DodoXuefeiDB`**,全走 Core 导出的**动作**。存的是 `manualOff` 而不是 `on`、
  尺寸有 clamp,面板照直觉自己写一份就当场分叉,而症状是「勾选框和屏幕上那格对不上」。
- **`Col:Edit` 只在文字真改过时才提交**:无条件挂 `OnEditFocusLost` 的话,面板一开一关的焦点事件
  就提交一次,而空串是"合法输入" ⇒ 一次误提交静默把值写坏,还自我固化。
- ⚠ canvas 页**不滚动**,超出的控件被静默裁掉 ⇒ 注册时按 `col.deepest` 吵一句(真实高度只有运行时知道)。
- **解锁期间它无视专精和天赋先显示出来**(不然非血 DK 根本摆不了位置);锁着时**不吃鼠标**,
  不会挡住身后的东西 —— 显隐和 `EnableMouse` 必须一起翻,漏掉的症状是「有块地方点不动」。
